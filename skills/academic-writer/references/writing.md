# Workflow: Writing a Paper from Scratch

Let the user enter at any stage — someone with a rough draft doesn't need
framing.

## 1. Frame the paper

Before drafting, settle (ask if not stated):

- **Venue** — drives format and conventions.
- **Contribution** — one specific sentence a reviewer would remember.
  "We improve X" is not a contribution; what's new and why it matters is.
- **The storyline** — the logical chain from problem to gap to idea to
  evidence to conclusion. Every later decision answers to it.

## 2. Outline against the storyline

- Section-level outline: one line per section stating its role in the
  storyline.
- Map each planned claim to its evidence (figure, table, derivation).
  A claim without evidence is a red flag — raise it now.
- Get the user's sign-off before drafting; restructuring is cheapest here.

## 3. Draft

Order: core (methods, results) first; framing (introduction, abstract,
title) last — they must describe the paper that exists, not the one planned.

- Follow the venue's genre conventions (section structure, abstract format,
  citation style). If the project has a template, use it.
- Mark unverifiable claims `[CITATION NEEDED: ...]` / `[VERIFY: ...]`.

## 4. Revise in separate passes

1. **Storyline** — does every section earn its place? Is the arc intact?
   Cut or move what doesn't serve the argument, however well-written.
2. **Argument** — every claim supported? Limitations acknowledged?
3. **Polish** — language, notation consistency, references and citations.

Present each pass as itemized changes the user can accept or reject
piecewise. When the user asks to fix one passage, fix that first; mention at
most 2–3 higher-priority issues you noticed — no unsolicited full critiques.
